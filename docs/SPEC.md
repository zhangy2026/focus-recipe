# 专注配方（Focus Recipe）产品规格说明书

> 版本 v1.0 · 单文件 HTML 番茄时钟 · 契约驱动
> 本文件是实现的唯一权威依据。每条需求含唯一 ID 与**可验证的验收标准（AC）**。

---

## 一、产品定位

### 1.1 要解决的问题

番茄时钟工具高度同质化，几乎全部集中在「专注中」的 25 分钟计时，而**真正的失败不发生在那 25 分钟里**。一个完整周期拆成五段后的痛点分布：

| 阶段 | 真实痛点 | 现有工具覆盖 |
|---|---|---|
| 开始前 | 高（启动阻力） | 几乎无 |
| 专注中 | 低 | 全部 |
| 被打断 | 高（恢复成本） | 几乎无 |
| 收尾 | 中 | 部分（仅统计） |
| 下次启动 | 高 | 无 |

### 1.2 产品命题

**不做第 1001 个计时器，做「专注阻力管理器」。**

核心判断：番茄钟的本质不是计时器，而是**注意力与心理负担的管理工具**。因此设计的重心放在"非计时"环节——降低启动阻力、消除打断的惩罚感、用收尾动作衔接下一次启动。

### 1.3 差异化支柱

1. **打断不归零**——把惩罚机制改成记录机制
2. **收尾只写下一步**——唯一真正降低下次启动阻力的机制
3. **任务画像三件套**——类别不只决定时长，还决定休息处方和打断策略

## 二、功能需求（FR）

### FR-1 任务类别与配方

| ID | 需求 | 验收标准（AC） |
|---|---|---|
| FR-1.1 | 提供 5 个任务类别：深度创作、学习输入、事务处理、会议沟通、碎片事务 | 页面渲染 5 个类别卡片，顺序固定 |
| FR-1.2 | 每个类别有独立配方：专注 / 短休 / 长休 / 几轮长休 | 默认值为 深度50/10/30/4、学习25/5/20/4、事务15/3/15/6、碎片10/2/10/6；会议为纯计时 |
| FR-1.3 | 类别决定**打断策略**：深度创作 = restart（建议重开），其余 = continue（原地继续） | 打断弹窗中，仅深度创作显示「本轮重新开始」按钮，其余不显示 |
| FR-1.4 | 类别决定**休息处方**文案 | 专注阶段下方显示的休息处方随类别切换；深度=起身别看屏、学习=回忆三要点、事务=活动肩颈、碎片=喝口水、会议=纯计时说明 |
| FR-1.5 | 配方时长可在设置中自定义 | 每个非会议类别有 4 个数字输入框；会议类别显示"纯计时模式"不可编辑 |
| FR-1.6 | 自定义值有合法范围约束 | 非会议类别的时长输入 < 1 时被钳制为 1；几轮长休钳制到 1–12；时长上限 600 |
| FR-1.7 | 自定义值持久化 | 修改后刷新页面仍生效 |
| FR-1.8 | 未开始时修改当前类别时长，计时器显示同步更新 | 全新状态下把深度创作 50 改成 30，环形下倒计时立即变 30:00 |
| FR-1.9 | 运行中或暂停中修改时长，不得破坏已跑进度或记账 | 运行中改时长：结算时按**开始时的快照值**记账，不按新值；暂停中改时长：已跑进度不丢失（不重置） |

### FR-2 计时核心

| ID | 需求 | 验收标准（AC） |
|---|---|---|
| FR-2.1 | 环形进度 + 数字倒计时 | 环形随进度推进；数字格式 M:SS，超过 1 小时为 H:MM:SS |
| FR-2.2 | 开始 / 暂停 / 继续 / 重置 | 按钮文案在「开始 / 暂停 / 继续」间正确切换 |
| FR-2.3 | **计时基于系统时间戳差值**，不得用 setInterval 递减 | 代码中使用 `deadline - Date.now()` 重算；切后台、锁屏后回到前台，剩余时间与实际经过时间一致 |
| FR-2.4 | 阶段自动流转：专注 → 短休/长休 → 专注 | 番茄完成后自动进入休息并开始计时；休息结束后回到专注状态 |
| FR-2.5 | 长休息在第 N 轮后出现（N = 该类别的「几轮长休」） | 深度创作（N=4）：第 1/2/3 个番茄后为短休息，第 4 个后为长休息 |
| FR-2.6 | 番茄点阵显示当前轮次进度 | 显示 N 个点，已完成轮次点亮，当前轮次高亮描边 |
| FR-2.7 | 会议沟通为**纯正计时**模式，不分番茄、不计番茄数 | 显示正计时 HH:MM:SS；阶段文字为「会议计时」；结束后只记累计分钟，番茄数不增加 |
| FR-2.8 | 会议模式暂停后继续，**不得归零** | 跑到 10:00 → 暂停 → 继续 → 应从 10:00 继续，不得从 0 重来 |
| FR-2.9 | 跳过本段 | 专注阶段跳过：按实际跑的时长记为未完成 session；休息阶段跳过：直接进入下一专注 |
| FR-2.10 | 重置 | 停止计时、清空当前打断、回到专注阶段满时长 |
| FR-2.11 | 时长为 0 时不得静默失败 | 若某类别时长被设为 0，点开始应给出明确提示，而不是无响应 |

### FR-3 打断机制（核心卖点）

| ID | 需求 | 验收标准（AC） |
|---|---|---|
| FR-3.1 | 可记录一次打断，分三类原因：外部打断 / 内部走神 / 主动暂停 | 弹窗有三个可选标签，默认选中「外部打断」 |
| FR-3.2 | **打断后番茄继续跑，不归零、不判失败** | 专注进行到剩余 30:00 时记录打断，倒计时仍为 30:00 且继续减少 |
| FR-3.3 | 深度创作类别提供「本轮重新开始」选项 | 点击后计时器回到满时长并**继续运行**（不得停表，也不得被旧 deadline 覆盖） |
| FR-3.4 | 打断计入统计，且**进行中的番茄也要实时反映** | 记录打断后，今日 KPI「被打断」立即 +1，无需等番茄结束 |
| FR-3.5 | 未开始计时时点击「记一次打断」应被拦截并提示 | 全新状态下点击，提示「还没开始计时」 |
| FR-3.6 | 休息阶段结束时应清空打断记录 | 休息期间记录的打断不得被下一个番茄带走而拉低完整率 |

### FR-4 收尾与启动阻力（核心卖点）

| ID | 需求 | 验收标准（AC） |
|---|---|---|
| FR-4.1 | 番茄自然结束时弹出收尾弹窗 | 弹窗出现，输入框自动获得焦点 |
| FR-4.2 | 弹窗只问「下一步的第一个动作」，不问「你做了什么」 | 文案与 placeholder 均为面向未来的表述 |
| FR-4.3 | 填写内容保存为 nextAction，下次打开显示在类别选择器下方 | 存下后刷新页面，仍显示「上次你打算：xxx」 |
| FR-4.4 | nextAction 可清除 | 点击「清除」后消失，且刷新后不再出现 |
| FR-4.5 | **关闭弹窗的任何路径都必须落库并推进状态，不得丢失番茄或卡死计时器** | 点「存下」/「跳过」/按 Esc / 点遮罩，三条路径都必须：① session 落库 ② 进入休息并开始计时 ③ 计时器可用 |

### FR-5 数据面板

| ID | 需求 | 验收标准（AC） |
|---|---|---|
| FR-5.1 | 今日四项 KPI：番茄数、专注分钟、被打断次数、完整率 | 数值正确；无记录时完整率显示「—」 |
| FR-5.2 | 完整率定义：当日「自然完成且全程无打断」的番茄数 / 当日全部番茄记录数 | 与定义一致 |
| FR-5.3 | 类别专注分布横向条形图 | 按当日各类别累计专注分钟降序；宽度按比例 |
| FR-5.4 | 近 12 周专注热力图 | 格子按当日完成番茄数分 5 级着色；**不得包含未来日期的格子**；每格有 title 提示日期与数量 |
| FR-5.5 | 打断洞察 | 当日打断 ≥ 3 次时，显示总次数与最主要原因，且措辞为中性/正向（不出现「失败」） |
| FR-5.6 | 配方建议 | 当某类别近 8 条记录中「未完成」占比 ≥ 50% 且记录数 ≥ 4 时给出建议；建议值必须**严格小于**当前设定值 |

### FR-6 提醒与反馈

| ID | 需求 | 验收标准（AC） |
|---|---|---|
| FR-6.1 | 提示音：专注结束（上行音）、休息结束（下行音）、倒计时预告（轻响） | 三种音色/音量可区分 |
| FR-6.2 | 专注阶段最后 5 秒每秒一次轻响 | 剩余 5/4/3/2/1 秒各响一次 |
| FR-6.3 | 桌面通知（可选开关） | 开启后番茄完成/休息结束触发系统通知 |
| FR-6.4 | 标题栏倒计时（可开关） | 运行时浏览器标签显示剩余时间与阶段 |
| FR-6.5 | 关键操作有 toast 反馈 | 记打断、重开、清空、导入失败等均有提示 |

### FR-7 分享卡片

| ID | 需求 | 验收标准（AC） |
|---|---|---|
| FR-7.1 | 生成当日专注卡片（Canvas 绘制 PNG） | 包含：日期、番茄数、专注分钟、打断次数、类别分布条、「下一步我打算」 |
| FR-7.2 | 卡片可下载 PNG | 桌面端点击下载成功 |
| FR-7.3 | 移动端可长按保存 | 弹窗内展示的是 `<img>` 而非 `<canvas>`（iOS Safari 长按 canvas 不出保存菜单） |
| FR-7.4 | **卡片内容不得重叠、不得溢出画布** | 5 个类别全部有数据时，类别分布区不得与底部「下一步」卡片重叠；「下一步」文字超长时须截断，不得溢出卡片 |

### FR-8 交互与持久化

| ID | 需求 | 验收标准（AC） |
|---|---|---|
| FR-8.1 | 快捷键：空格 = 开始/暂停，B = 记一次打断 | 生效；输入文本时不触发；**弹窗打开时不触发** |
| FR-8.2 | 数据存 localStorage | 刷新后番茄数、设置、nextAction 全部保留 |
| FR-8.3 | 导出 JSON / 导入 JSON / 清空 | 导出文件名含日期；导入非法文件给出提示且不崩溃；清空需二次确认 |
| FR-8.4 | 深色主题切换并持久化 | 切换后强调色随主题变化（不得残留浅色值），刷新后保持 |
| FR-8.5 | 通过 URL hash 直达类别 | `#deep` / `#meet` 打开即为该类别 |

## 三、非功能需求（NFR）

| ID | 需求 | 验收标准（AC） |
|---|---|---|
| NFR-1 | 单文件、零依赖、零外链资源 | 无 `<script src>`、无 `<link>`、无 fetch；断网可用 |
| NFR-2 | 离线可用 | 断开网络后功能完整 |

| NFR-7 | 数据不上传 | 无任何网络请求；页面声明数据仅存本地 |
| NFR-8 | 后台切回计时准确 | 隐藏页面一段时间后返回，剩余时间正确，不崩溃、不跳变 |
| NFR-9 | 零控制台错误 | 完整走一遍主流程无 console error / pageerror |
| NFR-10 | 安全区适配 | 底部 toast 不被 iPhone Home 指示条遮挡 |

## 四、架构设计

### 4.1 整体结构

```
┌─ 单文件 HTML ────────────────────────────────────┐
│                                                   │
│  ┌─ 表现层 (CSS) ─────────────────────────────┐  │
│  │  CSS 变量主题 (light/dark) + 响应式媒体查询  │  │
│  └────────────────────────────────────────────┘  │
│  ┌─ 视图层 (DOM) ─────────────────────────────┐  │
│  │  header / 类别选择器 / 环形计时器 / 数据面板 │  │
│  │  / 设置面板 / 三个 dialog / toast            │  │
│  └────────────────────────────────────────────┘  │
│  ┌─ 逻辑层 (IIFE，无框架) ────────────────────┐  │
│  │  ├ 配置层   PRESETS / BREAK_KINDS           │  │
│  │  ├ 状态层   S(持久化) + 运行时变量           │  │
│  │  ├ 计时引擎 start/stop/tick/complete        │  │
│  │  ├ 渲染层   renderCats/Ring/Stats/Settings  │  │
│  │  ├ 统计层   aggDay / suggest / drawCard     │  │
│  │  └ 服务层   beep / notify / save / load     │  │
│  └────────────────────────────────────────────┘  │
└───────────────────────────────────────────────────┘
```

单一 IIFE 封装，无全局污染。渲染层为「全量重绘」模式（`innerHTML = ""` 后重建），规模小、状态一致性好。

### 4.2 状态机

```
                    ┌──────────────────────────────┐
                    │                              │
   [IDLE/focus] ──start──> [RUNNING/focus]         │
        ▲                    │  │  │               │
        │                    │  │  └──timeup────┐  │
        │                pause  │                │  │
        │                    ▼  │                ▼  │
        │            [PAUSED/focus]        [FINISH_DIALOG]
        │                    │                   │
        │                 start              ok / skip / Esc
        │                    │                   │ (落库)
        │                    ▼                   ▼
        │            [RUNNING/focus]      [RUNNING/short|long]
        │                                         │
        │                                     timeup
        │                                         │
        └─────────────────────────────────────────┘
                    (回到 IDLE/focus，等手动开始)

  打断路径（不离开 RUNNING/focus）：
    [RUNNING/focus] ──break──> [RUNNING/focus]   （继续，不归零）
    [RUNNING/focus] ──break+restart──> [RUNNING/focus]  （归零但继续跑）

  会议模式（countup）为独立子状态机，无阶段流转：
    [IDLE] ──start──> [RUNNING] ──pause──> [PAUSED] ──start──> [RUNNING]
                          │
                       skip/结束 → 落库 → [IDLE]
```

**关键约束**：从 `FINISH_DIALOG` 出发的**每一条**边都必须落库并推进状态（FR-4.5）。

### 4.3 数据模型

```js
Session（一条专注/会议记录）
{
  cat:    'deep'|'learn'|'chores'|'meet'|'micro',
  at:     number,   // 会话开始时间戳（会议模式亦须为开始时间，不得为结束时间）
  planned:number,   // 计划分钟数
  actual: number,   // 实际分钟数
  cuts:   [{ t:number, k:'ext'|'int'|'act', restarted?:boolean }],
  done:   boolean,  // true=自然完成, false=中途跳过
  kind:   'focus'|'countup',
  next?:  string    // 仅 focus 且有填写时
}

PersistedState（localStorage key: focus-recipe-v1）
{
  sessions:   Session[],
  cats:       { [cat]: {focus, short, long, every} },
  opts:       { sound:boolean, notify:boolean, title:boolean, theme:'light'|'dark' },
  lastCat:    string,
  nextAction: { cat:string, text:string, at:number } | null
}

运行时变量（不持久化）
cur, phase, running, deadline, leftMs, elapsedMs, startedAt,
roundIdx, curPlanMs, cuts[], lastTickSec, finishing
```

### 4.4 关键设计决策

| 决策 | 理由 |
|---|---|
| 计时用 `deadline - Date.now()` 差值 | 浏览器后台节流会让 `setInterval` 递减越走越慢；差值法每次重算，永不累积误差 |
| `curPlanMs` 快照 | 运行中改设置时，结算须按开始时的值记账，否则实际跑 50 分钟却记 25 分钟 |
| `startedAt` 独立变量 | countup 模式恢复时若用 `deadline - leftMs` 反推，`leftMs` 已被赋值过，会归零 |
| 打断只记录不重置 | 产品核心命题：打断是数据，不是失败。惩罚机制会让人放弃使用 |
| 收尾问「下一步」而非「做了什么」 | 回忆有认知负担会被跳过；面向未来 5 秒可答，且直接降低下次启动阻力 |
| 分享卡片用 `<img>` 承载 | iOS Safari 长按 canvas 不出保存菜单，且 `a.download` + dataURL 不触发下载 |
| `overflow-x: clip` 而非 `hidden` | hidden 会让 overflow-y 被计算成 auto，body 变滚动容器，破坏 sticky 吸顶 |
| 弹窗拦截 `cancel` 事件 | Esc 默认关闭会绕过落库逻辑，导致番茄丢失且计时器卡死 |

## 五、验收方式

1. **静态校验**：提取内联 JS 跑语法检查；比对 DOM id 引用与声明
2. **规格符合性审计**：由独立审查者逐条比对实现与本文档的 AC（见审查报告）
3. **真实浏览器验证**：Playwright 跨 7 个视口，用虚拟时钟快进验证完整生命周期，覆盖全部 FR 的主路径与边界

## 七、审计与修复记录

本文件不仅是设计文档，也是验收契约。交付前按如下流程执行了三轮独立审计：

### 7.1 第一轮审计（并行 FR/NFR）

| 子智能体 | 结论 | 主要缺陷 |
|---|---|---|
| FR 审计 | 4 项未通过 / 3 项瑕疵 | Esc 关闭收尾弹窗导致番茄丢失且计时器卡死；「本轮重新开始」无效；0 分钟锁死计时器；分享卡片 5 类时重叠；文案与实际行为矛盾；休息段 cuts 未清零等 |

### 7.2 第二轮审计（回归验证）

修复第一轮缺陷后，两个子智能体**独立地**指出了一个由修复引入的致命回归：

- **问题**：新增 `dlgFinish` 的 `close` 事件守卫使用同步 `finishing` 标志，但 `close` 事件按 HTML 规范是异步派发的元素任务；`finishFocus` 同步末尾就把 `finishing=false` 复位，导致异步到达的 `close` 事件把每条番茄入账两次，并清空用户刚写的「下一步」、跳过休息自动开始下一个番茄。
- **修复**：改用幂等标志 `finishPending`（`complete()` 开弹窗前置位，`finishFocus()` 唯一消费），`close` 监听简化为无条件调用 `finishFocus("")`；`start()` 首行补 `clearTimeout(timer)` 以杜绝双定时器链。

### 7.3 第三轮审计（收尾检查）

| 发现 | 处理 |
|---|---|

| 输入 toast 对空值 / 前导零过于敏感 | 只在「解析出越界值」时才提示 |
| 会议模式 `at` 记为结束时间 | 改为 `startedAt` |
| `document.title` 每 250ms 写一次 | 加 `lastTitleSec` 秒级节流 |

## 十一、FR-11 自定义任务类别（2026-08-31 新增）

> 动机：5 种内置配方覆盖不了所有人的任务世界。允许每人最多自定义 5 种类别，与内置类别同等待遇（计时、统计、热力图、分享卡片、URL hash 全部生效）。

### 设计决策（先于代码）

| 决策点 | 结论 | 理由 |
|---|---|---|
| 数据模型 | `S.custom` 数组 ≤5：`{id,name,focus,short,long,every,color}` | 与内置的 `S.cats[k]` 覆盖层分离，导入/导出自然携带 |
| id 规则 | `"u"+时间戳36进制`，正则 `^u[a-z0-9]{4,12}$`，永不为内置键 | 避免 `__proto__` 型注入复现（FR 历史教训） |
| 纯计时 | 自定义**不支持** countup（用内置「会议沟通」） | 控制 v1 复杂度，suggest/休息处方逻辑不必为自定义分叉 |
| 颜色 | 5 色备用板 `#0f9d8f/#c24898/#5c7a99/#8a63d2/#b3324f`，按创建顺序取第一个未被占用的；rawD 由 `mix(color,#fff,0.6)` 现算 | 与内置 5 色在色相上全部错开 |
| 名称 | 1–8 字，渲染一律 `esc()` | 用户输入进 innerHTML，XSS 红线 |
| 删除语义 | confirm 确认；历史记录保留，统计/分享卡片显示灰色「（已删除类别）」；若删的是当前类别 → 回落 deep 并 resetPhase | 数据不丢，界面不留死引用 |
| 时长编辑 | 自定义的 4 个数直接在设置页行内改，写回条目并 save | 与内置类别体验一致 |
